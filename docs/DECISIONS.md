| DEC-067 | 2026-11-01 | **Root cause of photos saved partly black, and the fix.** `RecipeRenderer.RenderFinal` works on a clone of the loaded photo; ImageMagick shares a clone's pixels with the original until the first write. `ToneProcessor` reads and writes the image in strips; Magick.NET writes a strip with queued (write-only) access, for which ImageMagick gives a shared image new pixel memory *without copying* the pixels. Every strip after the first was therefore read as zeros and written black. It happened only when nothing else had made a private copy first: no crop (the full frame, e.g. a 2:3 camera photo at 10×15) and no turn or straightening, with any tone change; then about 1/8 of a 22 MP photo survived. The editor showed the kept original, while thumbnails, ID Photos, Collages and printing read the saved file; printing an unsaved edit had the same defect.
